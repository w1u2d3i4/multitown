# A26：风险校准的策略改进

状态：一次性 OOD split 上已完成的负结果。

## 结果

A26 选择阈值 `0.7`。在 1,000 个配对 OOD episode 上，自主成功率为 18.9%，A8 为
18.7%；差值 +0.2 个百分点，配对 95% 区间为 −2.2 至 +2.6。unsafe episode 为 18.3%，
A8 为 16.2%，因此比 `A8 + 0.02` 上限高 0.1 个百分点；平均 Token 也从 3,329.9 增至
3,409.2。

该结果未通过成功和安全门，不能声称改进。它促成 A28 的“分歧时专家优先”路径；已使用的 A26
test row 没有参与 A28 阈值选择。

## 为什么需要 A26

前序实验出现了两个相反的失败：无约束 PPO 提高了训练集成功率并减少 Token，但 unsafe episode
从 15.73% 升至 66.00%；硬复核屏蔽恢复安全后，又可能让自主成功率坍塌或增加复核开销。

A26 先验证一个更保守的问题：从训练集学习“每类任务应调用哪个专家”，只有当独立传感器与该
专家一致、且严重度低于校准阈值时才允许跳过复核；其余状态继续使用复核、第二专家升级和人工
兜底。

## 修复历史环境的信息泄漏

历史长时程环境用公开的任务族、失败模式和严重度确定正确动作，强学习器可能不依赖代理证据就
反推出答案。因此 A26 不沿用该性能 Fixture。

`generate_a26_episode()` 让正确动作与公开任务字段条件独立。train/dev 使用 12 个
任务族 × 失败模式组合，test 只使用四个留出组合；工具可靠性、预算、动作成本和八动作接口保持
不变。

## 冻结协议

1. 用偏移 `41_000_000` 生成 3,000 个训练 episode；
2. 只用训练标签拟合任务族级 weak/strong 专家路由；
3. 用偏移 `42_000_000` 生成 500 个 calibration episode；
4. 固定搜索阈值 `0,.4,.5,.6,.7,.75,.8,.85,.9,1.01`；
5. 可行候选必须同时满足：unsafe episode ≤ A8 + 0.02、每事件错误执行 ≤ A8 + 0.01、
   自主成功率不低于 A8；
6. 在可行候选中最大化自主成功率，再依次用更少 Token 和更高回报打破平局；
7. 在构造 OOD test bank 前先持久化 `selection-lock.json`；
8. 用偏移 `43_000_000` 一次生成 1,000 个测试 episode，在同一任务上运行 A8 和冻结 A26；
9. 对成功、安全事件、Token 和回报报告 episode 聚类的配对 bootstrap 区间。

运行命令：

```bash
multitown-a26-safe-router \
  --output /仓库外路径/a26-run
```

输出目录不进入 Git；公开仓库只保留生成器、协议、测试和聚合结论边界，不上传原始轨迹。

## 方法边界

A26 是“带约束的上下文策略改进控制器”，不是完整 Agentic RL。它学习专家路由和复核门，
其余工作流是确定性的，也不训练语言模型参数。

由于 A26 未通过，它没有成为下一阶段顺序 RL 的回退策略；这一角色现由独立确认通过的 A28
承担。只有真正完成多步信用分配、且训练不读取 test，后继方法才会称为 Agentic RL。

## 相关工作的采用方式

- [RouteLLM](https://arxiv.org/abs/2406.18665) 与
  [FrugalGPT](https://arxiv.org/abs/2305.05176)：支持按质量—成本动态路由和级联；
- [SPIBB](https://proceedings.mlr.press/v97/laroche19a.html)：支持低数据支持状态回退基线；
- [CQL](https://arxiv.org/abs/2006.04779) 与
  [IQL](https://arxiv.org/abs/2110.06169)：支持对离线价值采取悲观估计，避免利用未见动作；
- [Conformal Risk Control](https://arxiv.org/abs/2208.02814)：支持先校准再放行。
  A26 当前的 A8 相对 margin 不是 conformal 保证，未实现正式风险界限前不得这样宣称；
- [Agent Lightning](https://arxiv.org/abs/2508.03680)：支持把 agent 执行轨迹与 RL 训练解耦；
- [AgentPrune](https://arxiv.org/abs/2410.02506)：支持显式衡量冗余多智能体通信。

MultiTown 不继承上述工作的理论保证或实验结论。

## 结论门禁

只有 OOD split 同时满足以下条件，才称 A26 在该合成 Fixture 上通过验证：

- 成功率配对差值的 95% 区间下界大于 0；
- unsafe episode 不超过 A8 + 0.02；
- 每事件错误执行不超过 A8 + 0.01；
- 非法动作和预算违规均为 0。

即使全部通过，也只能声称 A26 合成环境内的改进，不能声称通用多智能体优势；TeamBench 通用
证据仍由独立的 `public-bench` 分支承担。
